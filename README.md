## tarkov.dev 对机器人调用的限制与现状

本插件的数据全部来自 [tarkov.dev](https://tarkov.dev) 公开的玩家档案。tarkov.dev 对机器人调用有限制，目前没有向第三方机器人开放独立的调用方式，插件也不会尝试绕过这些限制。因此：

- **只有在 tarkov.dev 网站上被搜索过的玩家才有档案**，没被搜索过的玩家查不到，和玩了多久无关。
- **档案不会自动更新**，是上次有人在网站上搜索或查看这名玩家时的快照。
- **第一次查某个玩家（包括你自己）之前，需要先到 tarkov.dev 搜索他一次**，几分钟后再查；想刷新数据时也一样。

如果你需要不受这些限制的调用，请自行向 [逃离塔科夫官方网站](https://www.escapefromtarkov.com/) 的制作组 Battlestate Games，或 [tarkov.dev](https://tarkov.dev) 的维护人员申请独立的调用权限。插件维护者没有这类权限，也无法代为申请或提供。

# 塔科夫玩家数据查询

在 AstrBot 聊天中绑定自己的《逃离塔科夫》账号，查询自己或其他玩家的档案：等级、阵营、PMC 与 Scav 的战局数、存活率、K/D 和技能等级。支持 PVP、PVE、PVP 赛季和塔科夫竞技场，可以用昵称、账号 ID 或 tarkov.dev 玩家页网址查询。

## 功能

- 绑定账号后发送 `@机器人 tarkov` 查自己；查别人可用玩家页网址、账号 ID 或昵称。按 ID 或网址查到过的玩家，插件会记住名字，之后所有人都能直接用名字查。
- 显示阵营、等级、声望、总游戏时长、成就数、最近活跃时间；PMC 与 Scav 的战局、撤离、存活率、击杀、死亡、K/D、撤离状态和最长连续存活；精英技能和等级最高的若干项技能。
- 竞技场：分非排位和排位显示对局、击杀、死亡、K/D、最佳 ARP 和段位、最长连杀、最长连胜，以及各模式的胜场、胜率和 MVP。
- 每次回复附上这名玩家的 tarkov.dev 页面链接和档案更新时间，超过 30 天没有更新会注明；按旧名字查到改过名的玩家时会注明现在的昵称。
- 三种回复方式（图片、文字、Markdown 文字）；支持所有人、仅管理员、管理员和指定用户三种权限，也可限定聊天。
- **服务器状态**（0.4.5 新增，默认关闭）：`@机器人 tarkov status` 回复服务器及各组件的状态图片，可开启状态变化推送。
- **Boss 刷率**（0.4.5 新增，默认关闭）：`@机器人 tarkov boss` 回复各地图日常 Boss 与三狗的刷率全表图，另显示实验室等地图上的活动 Boss；刷率有变化时可推送。
- **QQ 官方机器人**：支持 `@机器人 /命令` 写法（见“命令写法”设置）。

## 安装与配置

需要 **AstrBot ≥ 4.16.0**。

1. 将插件安装到 AstrBot 的插件目录，或在插件管理页导入发行压缩包。
2. 在 AstrBot 的 Python 环境安装依赖：`pip install -r requirements.txt`（`aiohttp`、`yarl`、`pillow`，AstrBot 本身都已带）。
3. 按需修改默认模式、谁可以使用等设置，保存后生效。默认所有人都可以使用。

## 开始使用

在群里先 @机器人，再发送命令，命令前面不加 `/`，例如 `@机器人 tarkov 帮助`（腾讯限制未经验证的 QQ 机器人只能这样被调用）。支持 `/` 唤醒的平台可以直接发 `/tarkov 帮助`，两种写法插件都能识别。帮助和提示里显示哪种写法，在配置“命令写法”中选择。

第一次查某个玩家之前，先在 tarkov.dev 搜索他一次，见上方“限制与现状”：

1. 打开 `https://tarkov.dev/players`，切换到这名玩家玩的模式（PVP / PVE / 赛季），输入游戏名搜索。页面会跳转到玩家页，网址形如 `https://tarkov.dev/players/regular/1234567`（`regular` 是 PVP，另有 `pve`、`pvp-season`）。每个模式的档案要在那个模式下搜索一次才会生成。
2. 把这个网址发给插件：

```text
@机器人 tarkov 绑定 https://tarkov.dev/players/regular/1234567   （绑定为自己的账号，任一模式的网址都可以）
@机器人 tarkov                                                   （查自己：先看默认模式，没有档案就换成有档案的模式）
@机器人 tarkov pve                                               （查自己的 PVE 档案）
@机器人 tarkov 赛季                                              （查自己的 PVP 赛季档案）
@机器人 tarkov https://tarkov.dev/players/pvp-season/7654321     （查别人，用网址，模式取自网址）
@机器人 tarkov 7654321                                           （查别人，用账号 ID）
@机器人 tarkov pvp Player_One                                    （查别人，用昵称：插件已经记住这个名字时）
@机器人 tarkov 解绑                                              （解除自己的绑定）
@机器人 tarkov 竞技场 7654321                                    （查竞技场档案，也可用昵称或竞技场网址）
@机器人 tarkov 帮助                                              （显示用法）
@机器人 塔科夫 pve Player_One                                    （塔科夫 与 tarkov 相同）
```

**模式**：`pvp`（也可写 `regular`、`常规`、`普通`）、`pve`、`赛季`（也可写 `season`、`pvp-season`）、`竞技场`（也可写 `arena`），不区分大小写。同一个账号在各模式下的档案是分开的，插件每次同时查看三个模式：

- **不写模式**：先看默认模式（默认 PVP）；没有档案时自动显示有档案的模式，并注明。
- **写了模式，或用网址查询**：只显示这个模式；没有档案时说明哪些模式有，并给出对应命令。
- 回复里会注明这个账号在哪些其他模式下也有档案。
- 绑定的是账号本身，与模式无关；名字与账号 ID 的对应关系也与模式无关。

**绑定**：可以发网址、账号 ID 或插件已记住的昵称，绑定前会先读一次档案确认存在。同一个平台账号在所有群和私聊里共用一个绑定。命令写作 `绑定`/`bind`、`解绑`/`unbind`。

**昵称**：字母、数字、下划线和连字符，3～24 个字符，不区分大小写。插件只认得“被绑定过，或按 ID/网址查到过”的名字；查不到时会回复操作步骤。名字恰好是 `help`、`pvp`、`pve`、`season` 等命令词时，要写上模式，例如 `@机器人 tarkov pvp season`。按名字查不到时，会提示只差 `_`/`-` 的相近名字。

**账号 ID**：纯数字。某个 ID 没有档案、而这串数字也符合昵称规则时，插件会再按昵称查一次。

**竞技场**是另一个游戏，但账号 ID 和昵称与塔科夫通用：

- 默认只在写明“竞技场”或发送竞技场网址（`https://tarkov.dev/players/arena/<账号ID>`）时才查。配置“不写模式时也查竞技场”打开后，不写模式的查询也会看竞技场。
- 竞技场档案要先在 tarkov.dev 用竞技场模式搜索一次这名玩家才会生成。显示的数字就是档案里的数字，插件不做修正。
- **段位**按“最佳 ARP”（档案只记录历史最高 ARP）对照下表；游戏里相邻段位的 ARP 范围重叠 100 分，插件按“最佳 ARP 超过上一段位的上限”算作达到下一段位。S（Elite）以上按排行榜名次划分，档案里查不到名次，统一显示为金色的“竞技场前100名玩家”。

  | 段位 | 显示名称 | ARP |
  |---|---|---|
  | D | Marauder | ≤1000 |
  | D+ | Jackal | 1001–2000 |
  | C | Mercenary | 2001–3000 |
  | C+ | Fighter | 3001–4000 |
  | B | Warrior | 4001–5000 |
  | B+ | Gladiator | 5001–6000 |
  | A | Veteran | 6001–7000 |
  | A+ | Professional | 7001–7900 |
  | S 及以上 | 竞技场前100名玩家 | 7900 以上（不显示具体 ARP） |

## 服务器状态与 Boss 刷率（可选功能）

这两项功能读取 [json.tarkov.dev](https://json.tarkov.dev) 的公开游戏数据（不是玩家档案），**默认关闭**，由管理员在配置页逐项开启。关闭时不下载对应数据，也不启动后台任务。回复目前**只有图片**，不受“输出方式”设置影响；文字和 Markdown 版本暂未提供。

**命令**（`@机器人` 写法与 `/` 写法都能用，见“命令写法”）：

```text
@机器人 tarkov status                 （服务器状态；也可写 状态）
@机器人 tarkov boss                   （Boss 刷率全表，所有监控模式各一张）
@机器人 tarkov boss pve               （只看 PVE；也可写 pvp、赛季）
@机器人 tarkov boss 变化              （最近一次刷率变化，变化标红，图下方文字说明）
@机器人 tarkov boss 页 <快照编号> <页码>（长表续页，编号在图下方注明）
```

另外还有不加 `tarkov` 的短命令 `status`（状态）和 `boss`（刷率）；与其他插件冲突时，在配置里关闭“启用简短查询命令”，`tarkov status`、`tarkov boss` 仍可用。

**设置**（各项都在配置页，保存后重载生效）：

- **服务器状态图片查询**、**服务器状态变化图片播报**、**服务器状态轮询间隔**（2～30 分钟，默认 5）、**播报目标**、**允许向 QQ 官方机器人会话播报状态**。
- **Boss 刷率功能总开关**：关闭后整个 Boss 功能停用，不能查询，也不会轮询或推送。
- **Boss 刷率变化推送**：只控制后台轮询和推送，关闭后查询照常；开启还要求总开关已开、有监控模式和播报目标。**Boss 刷率轮询间隔**（2～30 分钟，默认 10）、**监控模式**（默认 pvp、pve、赛季）、**播报目标**、**允许向 QQ 官方会话播报 Boss 刷率**。
- **播报目标**要填完整的 AstrBot 会话标识（聊天中发送 `/sid` 查看），最多 50 个；留空就不轮询、不播报。播报不会发给所有会话，只发给你填写的目标。首次成功只建立基线，不推送；之后有变化才推送。插件只能“提交”消息，不能确认对方收到。
- **公共游戏数据缓存时间**（默认 5 分钟）：状态和 Boss 共用，只在过期后的查询里检查更新。
- **手动拉取/更新 Boss 头像**：执行一次后自动关闭，头像从 assets.tarkov.dev 取得，缓存 365 天；平时不会自动下载，没有头像时用占位图。
- **不当作活动 Boss 的怪物**（高级）：见下。

**Boss 图怎么看**：

- 行是 Boss，列是地图（中心区、白天工厂、夜间工厂、海关、森林、海岸线、立交桥、储备站、灯塔、塔科夫街区、实验室），格子里是刷率，左上角写模式。固定的行是 Tagilla、Reshala、Shturman、Sanitar、Killa、Glukhar、Zryachiy、Kaban、Kollontay、Partisan、邪教徒祭司和三狗 GOONS。同一格里有多个概率时分别显示，不相加。空白表示上游没有列出。
- 100% 的刷率用红色粗体，该 Boss 的名字也标红。
- **活动 Boss**：固定行之外，地图上列出的 Boss 记录，除 Raider、黑色军团、USEC、BEAR、游荡者、守军这几类普通怪物之外，都显示为“活动 <名字>”行，最多 3 行，超出时注明数量。上游新增了不想显示的普通怪物时，把它的 `normalizedName`（例如 `raider`）填进“不当作活动 Boss 的怪物”。
- **变化推送**：图和全表相同，变化的格子标红，图下方用文字列出“本次变化”，例如“三狗 GOONS（海岸线）：60%→80%”；活动 Boss 出现或结束也会列出。格子里只显示新值。
- 没有包含在表里的：破冰船、原中心区、实验室 Dark、迷宫、中心区教程、码头，以及普通 AI。

## 回复方式

在配置“输出方式”中选择，默认是图片：

- **图片**：情报档案风格，用自带的开源字体在本地绘制，不经过在线渲染服务；图片最下方写明插件名称、版本、仓库和开源许可，后面附一行玩家页链接。画图失败时自动改发文字。图上的元素都是插件自己画的，没有使用游戏素材；昵称里字体画不出的字符显示为 `?`。
- **文字**：纯文字，任何平台都能正常显示。
- **Markdown 文字**：带标题、表格和加粗，适合 Telegram、Discord 等；在 QQ 等平台上会显示出原始符号。

`@机器人 tarkov 帮助` 跟随这个设置：选“图片”时回复一张用法图片，否则回复文字版用法。找不到玩家、同名列表和出错提示，无论选哪种方式都以文字回复。服务器状态和 Boss 刷率只回复图片。

- **等级**由总经验按 tarkov.dev 的等级经验表换算；**技能等级**是进度除以 100，满 51 级为精英。

## 常用设置

- **默认模式**：命令里没写模式时使用，默认 PVP。
- **不写模式时也查竞技场**：默认关闭，开启后每次多一个请求。
- **输出方式**：图片（默认）、文字或 Markdown 文字。
- **命令写法**：`@机器人 tarkov`（默认）、`/tarkov`，或 QQ 官方机器人提及后加斜杠的 `@机器人 /tarkov`，只影响显示。
- **QQ 官方机器人提及后斜杠命令兼容**：默认开启，让 `@机器人 /tarkov …`、`/status`、`/boss` 在 QQ 官方平台也能触发；关闭不影响框架本来能识别的命令。
- **谁可以使用**：所有人（默认）、仅管理员，或管理员和指定用户。“管理员”指 AstrBot 管理员，不是 QQ 群管理员。
- **指定用户 / 限定聊天**：填写平台用户 ID（例如 QQ 号）和 AstrBot 会话标识（聊天中发送 `/sid` 查看），留空不限制聊天。手工编辑配置文件时应为列表；写成其他类型时拒绝所有人。
- **显示的技能数**：精英技能总是全部列出，这里设置其余技能显示几项，默认 10，设为 0 不显示。
- **档案缓存时间**：默认 10 分钟，只在内存中；“没有档案”的结果只缓存 1 分钟。用玩家页网址查询和绑定时不使用缓存。所有人合计最多同时进行 6 个档案请求。
- **同时使用 tarkov.dev 的昵称名单**：默认关闭。开启后，插件记录里找不到的名字会再查名单；名单只收录在网站上被搜索过的玩家，PVP 名单约 30 MB，本地约占 100 MB。另有“昵称名单更新间隔”（默认 168 小时）和“下载最长等待”（默认 120 秒）。
- **访问 tarkov.dev 时使用代理 / 代理地址**：默认关闭。开启后所有请求都经过这个 HTTP/HTTPS 代理（不支持 SOCKS，需写明端口），不使用 AstrBot 或系统的代理设置；代理连不上时不会改为直连。部分服务器的 IP 会被 Cloudflare 拦截，查询提示“HTTP 403”时可以开启。

## 数据存储

数据位于 `data/plugin_data/astrbot_tarkov_datasearch/`：

- `accounts.sqlite3`：
  - 绑定关系：平台和用户 ID 的带密钥哈希（HMAC-SHA256）→ 账号 ID 和昵称，不保存 QQ 号等原始 ID；`@机器人 tarkov 解绑` 会删除自己的绑定。密钥是第一次运行时随机生成的 `binding.key`，删除它会让所有绑定失效。拿到数据库但没有密钥无法还原 QQ 号，同时拿到密钥的人仍可逐个尝试，请像对待聊天记录一样保管整个数据目录。
  - 所有人共享的“名字 → 账号 ID”记录：每次绑定、每次查到档案时更新，最多 20 万条，超出时删除最久没见过的。这些名字本来就在 tarkov.dev 公开。
- `names-profile.sqlite3`、`names-pve.sqlite3`、`names-pvp-season.sqlite3`：只在开启昵称名单后生成，可以随时删除。
- `public-data/resources.sqlite3`：服务器状态和 Boss 的公共游戏数据缓存（最多 32 项、约 128 MiB），首次查询时才生成，可以随时删除。
- `notifications.sqlite3`、`boss-notifications.sqlite3`：只在开启并配置了对应播报后生成，保存变化基线、待发事件、逐目标的发送状态和长表快照（事件保留 7 天）；删除后下次观察会重新静默建立基线。
- `boss-portraits/`：只在手动更新 Boss 头像后生成，是缩小的头像缓存，可以随时删除。
- 玩家档案只缓存在内存中，图片在内存中生成后直接发送，都不写入磁盘。
- 插件不另存“谁查询了谁”；但 AstrBot 的日志会记下每条消息的发送者和内容，插件日志里也有被查询的昵称或 ID，请像对待聊天记录一样保管日志。
