# 玩家周报：规划与决定记录

日期：2026-11-10。状态：**PVP、PVE、赛季已实现**（用法见 [weekly-report.md](weekly-report.md)）；**竞技场只有规划，尚未实现**（第 5 节）。

## 1. 目标

定期拉取指定玩家的统计数据，做成“近 7 天”周报：聊天里按需查询，并可每周定时把排行发到指定的群。娱乐用途，不追求精确。

## 2. 前提与约束

- tarkov.dev 的快照只有在有人查看时才更新，不能用来定期采样；只能用 Atlas。
- Atlas 没有逐局记录，只有累计数。周报 = 两次采样之间累计数的差。
- 此前的规则是“不用 Atlas 做后台轮询、预取或批量查询”。**维护者 2026-11-10：上游已放宽使用限制，允许按下面的规则定期拉取。** 这是 Atlas 唯一的后台请求来源，其他功能仍然只在用户发命令时请求。
- Atlas 的数据输出必须带 Atlas 标志和链接；只出图片。

## 3. 维护者的决定（2026-11-10）

| 事项 | 决定 |
|---|---|
| 后台拉取 | 做。北京时间 03:00 开始；每次只拉取一名玩家；相邻两次间隔 120 秒 + 随机 20～60 秒；不设每小时上限 |
| 错过采样 | 只在 03:00～09:00 内拉取，过了时段等第二天，不在白天补拉 |
| 采样对象 | 只有名单内的玩家。名单在设置里按模式分别填写（账号 ID 或昵称），不做聊天订阅／退订／状态命令 |
| 模式 | 四个模式都要，各有独立名单。**本次只实现 PVP、PVE、赛季；竞技场只写在规划里** |
| 查询口径 | 滚动近 7 天；每日战局按正常采样画，不需要精确边界，图上不写详细的统计区间 |
| 查询命令 | `tarkov 周报 [模式] [昵称或账号ID]`：有使用权限的人可查名单内任意玩家；不写目标时查自己绑定的账号（须在名单内），否则回复该模式排行 |
| 自动播报 | 每周一次，星期和时:分在设置里填；每个模式一张排行图；目标必须明确填写，留空不播报 |
| QQ 主动推送 | 维护者已在部署的机器人上实测可用，周报播报不另设 QQ 开关 |
| 数据保留 | 由后台控制，到期自动删除；从名单去掉玩家或解绑都不触发删除 |
| 不做 | 文字／Markdown 输出、大模型评语 |

## 4. 实现概要

| 部分 | 位置 | 说明 |
|---|---|---|
| 样本与计算 | `tarkov_core/weekly_report.py` | `extract_sample` 把一份 Atlas 档案压缩成数字；`build_report` 从最近一次采样往前取 7 天（起点取离“7 天前”最近的样本，前后不超过 48 小时，否则取周内最早的），逐段求和；累计数变小视为重置，该段按新值计；`build_card`、`build_ranking` 生成图片内容 |
| 存储 | `tarkov_core/weekly_store.py` | 独立的 `weekly.sqlite3`：名单昵称解析结果、每晚进度（每人每天一次、失败再试一次）、样本、播报记录 |
| 后台任务 | `tarkov_core/weekly_tasks.py` | `WeeklySampler`：采样时段、每步最多一次 Atlas 请求、120 秒 + 随机 20～60 秒；`WeeklyBroadcast`：到点发送，错过 6 小时不补发，每张图最多 3 次 |
| 图片 | `tarkov_core/weekly_image.py` | 个人周报与排行，沿用玩家档案的深色版式；复用其 PMC／SCAV 大字表和撤离状态条 |
| 接入 | `main.py` | 设置读取、名单解析、命令 `周报`／`weekly`／`tweekly`、用户查询顺带记样本、任务的启动与停止 |

几点取舍：

- **另建样本库，不用查询记录**：查询记录默认只留 180 小时，还受隐私开关和总大小限制，不适合做周报基线；样本只存数字，每条 1～3 KB。
- **“近 7 天”以最近一次采样为终点**：每天凌晨采一次时，正好是 7 段、7 根柱子；凌晨样本记到前一天（样本时间减 12 小时所在的日期）。
- **每步最多一次请求**：昵称需要搜索时，搜索单独占一步，档案在下一步拉取，中间同样间隔。
- **被本插件自己的额度或排队拒绝**（请求没有发出）不算一次尝试，下一步再试。
- **最新样本超过 3 天**（采样停了）不出周报，避免把旧数据当成本周。

## 5. 竞技场周报（规划，未实现）

竞技场的档案结构与主游戏不同，需要单独设计，放到后续版本：

- **数据**：Atlas 竞技场档案没有 `stats`，统计在 `arenaStats.modes`：每个玩法一组计数（`GamesCount`、`ArenaWins`、`ArenaLoses`、`Kills`、`Deaths`、`Assists`、`Headshots`、`MatchMvpCount`、`RoundMvpCount`、`BestArp` 等约 40 项），键名分排位（`Overall`、`TeamFight`…）和非排位（`Unranked…`）。现有 `arena.sections()` 已能把它整理成分区和玩法行。
- **样本**：按玩法保存一小组累计数（场次、胜、负、击杀、死亡、助攻、MVP），加 `BestArp`、当前通行证等级、近期成就。
- **周报内容**：近 7 天的场次、胜率、击杀、死亡、K/D、MVP，按排位／非排位分区和玩法列出；`BestArp` 是历史最高值，只能显示“本周创新高”与否，不能求差；每日场次图与主游戏相同。
- **设置**：增加第四个名单 `weekly_arena_players`，与其他三个并列；命令 `tarkov 周报 竞技场 [昵称或账号ID]`。目前这个写法回复“竞技场周报还没有实现”。
- **图片**：沿用竞技场“选手名册”风格还是深色板式，待维护者确认示意图后再定。
- **排行**：按场次排序，列胜率、K/D、MVP。
- **需要先核实**：实测中竞技场 `lookup` 较慢（一次 14.6 秒）并出现过 502，上线前要确认夜间采样的失败率；排位玩法的键名在 Atlas 上还没有见到真实样本。
