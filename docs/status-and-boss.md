# 服务器状态与 Boss 刷率（可选功能）

这两项功能读取 [json.tarkov.dev](https://json.tarkov.dev) 的公开游戏数据（不是玩家档案），**默认关闭**，由管理员在配置页逐项开启。关闭时不下载对应数据，也不启动后台任务。查询结果是图片；数据取不到或图片生成失败时回复一行文字；默认模式绑定成功时用文字确认。命令写法、权限、代理等通用设置见 [README](../README.md#通用设置)。

**命令**（`@机器人` 写法与 `/` 写法都能用，见“命令写法”）：

```text
@机器人 tarkov status                 （服务器状态；也可写 状态）
@机器人 tarkov boss                   （使用个人默认模式；未绑定时查询所有配置的监控模式）
@机器人 tarkov boss pve               （只看 PVE；也可写 pvp、PVP S、pvps、season、pvp-season、赛季）
@机器人 tarkov boss 默认 pve          （绑定个人 Boss 默认模式；也可写 default pve）
@机器人 tarkov boss 变化              （最近一次刷率变化，变化标红，图下方文字说明）
@机器人 tarkov boss 页 <快照编号> <页码>（长表续页，编号在图下方注明）
```

QQ 官方机器人的命令里不能有空格，所以有两个单词命令：`tstatus`（等于 `tarkov status`）和 `tboss`（等于 `tarkov boss`，后面的模式、`变化` 可以带空格，如 `@机器人 tboss pve 变化`）。在配置页“通用”里可以关闭，只对 QQ 官方平台生效。

个人默认模式按平台实例和用户保存，同一平台实例下跨群有效，插件重启后保留，无需先绑定游戏账号。显式模式优先：绑定 PVE 后查询 `boss PVP S` 只查赛季，不改变绑定；不写模式的 `boss 变化` 也使用个人默认模式。绑定不修改管理员配置的监控模式，也不影响玩家档案查询默认模式；未绑定时保留原来的多模式查询行为。查询仍使用上述命令前缀，不新增独立 `/boss` 短命令。模式不同的概率和缓存分别读取，不跨模式替代。

**设置**（各项都在配置页，保存后重载生效）：

- **服务器状态图片查询**、**服务器状态变化图片播报**、**状态检查间隔**（10～90 分钟，默认 30）、**播报目标**、**允许向 QQ 官方机器人会话播报状态**。
- **Boss 刷率功能总开关**：关闭后整个 Boss 功能停用，不能查询，也不会轮询或推送。
- **Boss 刷率变化推送**：只控制后台轮询和推送，关闭后查询照常；开启还要求总开关已开、有监控模式和播报目标。**刷率检查间隔**（10～90 分钟，默认 30）、**监控模式**（默认 pvp、pve、赛季）、**播报目标**、**允许向 QQ 官方会话播报 Boss 刷率**。
- **播报目标**要填完整的 AstrBot 会话标识（聊天中发送 `/sid` 查看），最多 50 个。**留空就推送给所有用过本插件命令的群**（插件会记住这些群的会话标识，只记群，不记用户，也不含私聊；每个群里至少要有人用过一次命令；仍受“限定聊天”和权限限制，QQ 官方的群还需要打开对应的“允许向 QQ 官方机器人推送”）。填写后只推送给这些会话。首次成功只建立基线，不推送；之后有变化才推送。插件只能“提交”消息，不能确认对方收到。
- **公共游戏数据缓存时间**（默认 5 分钟）：状态和 Boss 共用，只在过期后的查询里检查更新。
- **手动拉取/更新 Boss 头像**：执行一次后自动关闭，头像从 assets.tarkov.dev 取得，缓存 365 天；平时不会自动下载，没有头像时用占位图。
- **不当作活动 Boss 的怪物**（高级）：见下。

**Boss 图怎么看**：

- 行是 Boss，列是地图（中心区、白天工厂、夜间工厂、海关、森林、海岸线、立交桥、储备站、灯塔、塔科夫街区、实验室），格子里是刷率，左上角写模式。固定的行是 Tagilla、Reshala、Shturman、Sanitar、Killa、Glukhar、Zryachiy、Kaban、Kollontay、Partisan、邪教徒祭司和三狗 GOONS。同一格里有多个概率时分别显示，不相加。空白表示上游没有列出。
- 100% 的刷率用红色粗体，该 Boss 的名字也标红。
- 万圣节活动的 `infectedTagilla` 归到 Tagilla 行，后端保留变体来源及独立刷新规则；若与普通版同时出现，分别列出概率，不相加。普通感染者（`infectedAssault`、`infectedCivil`、`infectedPmc`、`infectedLaborant`）不占活动 Boss 名额；`infectedScreamer` 仍作为特殊活动怪物保留。Partisan 未被上游列出时隐藏该行，避免误导为游戏内不刷新；数据恢复后自动显示，明确提供的 0% 仍正常展示。其他 Boss 未被列出时保持空白。更新后监控会静默重建基线，避免分类变化触发错误播报。
- **活动 Boss**：固定行之外，地图上列出的 Boss 记录，除 Raider、黑色军团、USEC、BEAR、游荡者、守军这几类普通怪物之外，都显示为“活动 <名字>”行，最多 3 行，超出时注明数量。上游新增了不想显示的普通怪物时，把它的 `normalizedName`（例如 `raider`）填进“不当作活动 Boss 的怪物”。
- **变化推送**：图和全表相同，变化的格子标红，图下方用文字列出“本次变化”，例如“三狗 GOONS（海岸线）：60%→80%”；活动 Boss 出现或结束也会列出。格子里只显示新值。
- 没有包含在表里的：破冰船、原中心区、实验室 Dark、迷宫、中心区教程、码头，以及普通 AI。

## 数据存储（状态与 Boss）

数据位于 `data/plugin_data/astrbot_tarkov_datasearch/`：

- `public-data/resources.sqlite3`：公共游戏数据缓存（最多 32 项、约 128 MiB），首次查询时才生成，可以随时删除。
- `accounts.sqlite3` 的 `boss_preferences` 表：个人 Boss 默认模式，使用与玩家绑定相同的带密钥用户标识；不保存原始用户 ID，与游戏账号绑定独立。
- `notifications.sqlite3`、`boss-notifications.sqlite3`：只在开启并配置了对应播报后生成，保存变化基线、待发事件、逐目标的发送状态和长表快照（事件保留 7 天）；删除后下次观察会重新静默建立基线。
- `boss-portraits/`：只在手动更新 Boss 头像后生成，是缩小的头像缓存（365 天），可以随时删除。
- 图片在内存中生成后直接发送，不写入磁盘。
