## 2. rev7 调用规则

### 认证、模式和额度（PDF 第 1～2、4～6 页）

- API 仅在服务器端调用；没有开放跨域。通过 `X-Atlas-Key: atl_…` 或 `Authorization: Bearer atl_…` 认证，密钥不进入前端、源码仓库、日志或回复。
- `lookup`：玩家独立额度和玩家索引；`changes`：变更集 API 及网站白名单；`early`：须同时有 `changes` 才能从 API 提前读取变更集。网站能提前查看不表示 API 有 `early` 权限。
- 玩家接口根地址：`https://www.eftforge.com/atlas/api`。玩家 `mode` 为 `season`（上游默认）、`pvp`、`pve`、`arena`；必须显式传模式，不能沿用旧路径或依赖上游默认。
- 变更集根地址：`https://www.eftforge.com/atlas/api/v1`。`game` 为 `eft`（赛季）、`pvp`、`pve`、`arena`。插件的 `season` 在这里映射为 `eft`，其他三个同名。

额度以提供方当前规则为准，本项目不重复列出上游额度数值。插件本地预算由维护者单独决定。

相同玩家请求一分钟内由上游缓存，不重复计数；客户端不能假定所有实际请求一定命中该缓存。禁止批量抓取或遍历账号；定时统计同步用 `art=0` 并分散请求。

### 玩家查询与索引（PDF 第 2、4 页）

| GET 路径 | 规则 |
|---|---|
| `/lookup/search?nickname=…&mode=…` | 返回 `players`（账号 ID、昵称、阵营、等级）；`source=index` 不计查询额度，`live` 表示向游戏查询 |
| `/lookup?accountId=…&mode=…` | 玩家资料；仅需统计时加 `art=0`，此时 `render`、`character` 为 null |
| `/lookup/banned?accountId=…&mode=…` | 直接使用该接口，不能自行根据搜索结果判封禁 |
| `/players/{mode}/index.json` | ID → 当前昵称；须有 `lookup`；上游每小时最多更新一次，每天下载一次足够 |
| `/players/{mode}/updated.json` | ID → Atlas 最后看到账号的 Unix 毫秒时间，仅含 Atlas 自己查到的账号；同样须有 `lookup` |

昵称只接受 3～15 个 ASCII 字母、数字、`_`、`.`、`-`；账号 ID 为纯数字。`TarkovCitizen` 开头的系统昵称不能通过 Atlas 按昵称搜索，只能按 ID 查询。资料昵称与搜索目标不一致时，加 `live=1` 重新搜索并处理新的候选结果，不能静默把改名账号当作原目标。

封禁推测状态为 `possibly_banned`、`no_sign_of_ban`、`unknown`。界面分别表达“可能已被封禁”“未发现封禁”“无法检测”，明确这是推测，不能将未知或错误说成未封禁。

### 图片和角色渲染（PDF 第 2～3 页）

- `render`、`character.headshot`、`character.full` 是 `/atlas/api/lookup-art/…` 相对地址，补上固定主机 `https://www.eftforge.com`。图片为 WebP，需要下载保存，旧链接可能被清理。
- `character.full3d` 可缺失；存在时含 `spec`、`hand`、`weapons[{slot,tpl}]`、按手持选择分组的 `poses` 和默认 `url`。没有武器时 `hand` 为 null；`art=0` 时整个 `character` 为 null。
- `/lookup-render/{spec}/{hand}/{pose}` 返回固定地址的 WebP，可缓存；首次绘制耗时数秒。旧 spec/图片失效时重新查询玩家，不反复请求失效地址。
- `/lookup-render?accountId=…&mode=…&hand=…&pose=…` 每次按当前装备查询，返回 **302**；按账号的地址结果不缓存，相同查询一分钟内用上游缓存。
- `hand` 为 `FirstPrimaryWeapon`、`SecondPrimaryWeapon`、`Holster`、`Scabbard` 或 `none`；按账号调用可省略以使用默认武器。`pose` 为 `default` 或该 hand 下 `poses` 列出的 ID；未携带的武器、未列出的姿势返回 404。自定义姿势标注实验性。
- `clothing.head/body/feet` 提供 `ch`、`en` 名称；不推断或编造游戏未提供的语音名称。

### 变更集与其他公开接口（PDF 第 4～6 页）

- `/{game}/changes`：按旧到新列出，支持 `cursor`、ISO 8601 `since`、`limit`（默认 50，最多 200）；`/{game}/sets/{id}` 获取详情；`/{game}/sets/{id}/values/{n}` 获取大值。
- 首次不带 cursor；处理完本页 `sets` 的详情及所需大值、可靠保存后再提交该页 cursor；`has_more=true` 时继续分页。后续只按保存的 cursor 增量拉取，空页 cursor 不变。
- 无 `early` 时，检测后 12 小时才公开；未公开项只在 `pending`，包含 id、检测时间、版本、变动数量、文件数及 `public_at`，没有具体内容，响应另有 `message`。cursor 不会越过 pending，之后按原 cursor 继续即可。
- 提前请求详情或大值返回 425，按 `Retry-After` 等待。有 `early` 时立即进入 `sets`，pending 为空。若以后接入群聊播报，仍按 `public_at` 限制公开发布，避免 early 内容提前进入图片、摘要或公共回复。
- 大值占位为 `{"$atlas_value": n, "bytes": 大小}`，须独立获取，不能当作完整业务值。同步需幂等，详情或大值失败时不得提交导致遗漏的 cursor。
- `/matching?hours=24` 无需密钥；`hours` 为 1～168，上游每分钟更新，应做缓存、不高频轮询。它描述平均匹配等待时间，不等同服务器健康状态。

### 错误与缓存边界（PDF 第 6 页；缓存例外见第 2～4 页）

| HTTP | 应如何处理 |
|---|---|
| 401 | 需要认证的变更集/索引缺密钥；停止该功能请求，提示配置 |
| 403 | 密钥无效、过期、撤销或权限不足；停止相关请求并提示管理员处理，不能提示换代理重试 |
| 425 | 尚未公开；按 `Retry-After` 秒数等待，不作为缺失数据或跳过 cursor |
| 429 | 频率、繁忙或渲染额度限制；按 `Retry-After` 等待，不能靠切模式/换接口立即再试 |
| 404 | 依据具体接口区分无资料、无变更集或图片/spec/武器/姿势失效 |
| 400 / 422 | 分别为 cursor/since 格式问题，以及昵称、ID、mode、hand、pose 参数问题；修正参数再调用 |
| 503 | 玩家查询/渲染暂不可用；有界退避，不能当作玩家不存在 |

同一 IP 连续 5 次用错误密钥会被临时封禁 10 分钟；接入时应在首次明确认证失败后暂停，防止其他会话及后台任务继续发送同一密钥。不能自动换匿名或轮换密钥继续请求。

第 6 页写“所有接口的响应都不允许缓存，请不要在中间加缓存层转发”，而第 2～4 页明确要求下载保存图片、允许固定渲染图缓存、每日下载索引和 matching 缓存。执行方案按接口区分：不建立 Atlas JSON 缓存转发服务，不将认证 JSON 直接送入现有通用资源缓存；图片/索引/matching 按专门规则处理。玩家资料本地 TTL、变更集内容的必要持久化与此总述的具体边界列为修改存储策略前向提供方确认项；不能仅凭旧版允许缓存的说明忽略新总述，也不能据此擅自删除历史或禁止明确要求的图片保存和 cursor 状态持久化。
