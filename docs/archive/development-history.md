# 开发决策摘要

> 2026-11-11 整理。合并六份已实施或部分实施的规划/审查；这是决策和迁移线索，不是第二份待办。当前状态以 [checklist](../../checklist.md) 为准，功能用法以各使用说明为准。完整旧方案保留在文末固定提交链接，不依赖分支名漂移。

<a id="status-boss"></a>

## 状态、Boss 与 QQ（2026-10-24 起）

- 采用公开 JSON 资源、独立缓存和变化队列，功能和推送分别开关。状态是全局资源，Boss 按 PVP/PVE/赛季处理；坏响应、旧缓存不能推进成功基线。首次成功只建基线、不推送。
- 通知先可靠入队，再按目标/页记录提交；权限拒绝暂停目标，未知发送结果不冒充送达，也不承诺严格一次送达。具体当前规则见[状态与 Boss](../status-and-boss.md)。
- Boss 使用选定地图的矩阵，区分空白与 0%，变化标红；活动 Boss 的判断多次修订，最终规则与排除列表以使用说明和代码为准。头像只通过一次性设置下载，普通查询/轮询不暗中下载。
- 早期方案的 5/10 分钟轮询与“空目标不发送”已被替代：当前默认均为 30 分钟、可调 10～90；状态/Boss 目标留空时使用记住的群会话。周报则仍须明确填写目标。
- QQ 单词命令、斜杠补充入口与权限控制只适用于相应平台。真实 AstrBot 4.16.0 SDK 离线路由回放不是 QQ 实际送达证明。
- 2026-10-24 维护者更正：图片默认，但状态/Boss 仍需兼容文字与 Markdown，暂缓实现；早期“所有输出都改为图片”的计划取消。后来 Atlas、匹配、周报只出图是分别确认的范围。
- 物品功能做完后退出运行范围，见[物品归档](item-query.md)。TarkovTracker 只作参考，不接入其内部代理/私有 overlay。

<a id="atlas-matching"></a>

## Atlas 匹配时间（2026-11-08）

- 先实现客户端、共享准入和匹配服务，再接聊天。固定 24 小时历史，所有会话共用结果；成功缓存 15 分钟，临时失败最多回退到 60 分钟内的成功值。
- 请求由用户命令触发；不把匹配等待当服务器健康状态，不根据缺失值画零。模式/参数错误、关闭功能和非临时错误不以旧缓存掩盖。
- 共享间隔从早期草案的 5 秒修订为至少 10 秒；玩家与匹配共用请求入口，tarkov.dev 状态/Boss 不纳入 Atlas 冷却。
- v0.5.0 已接入 `tarkov 匹配` / `matching` / `tmatch`，默认开启，只出图片；早期“三种输出”和“默认关闭”不再是当前要求。图片保留 Atlas 标志、链接与致谢。
- 旧方案的 401/403 两分钟重试已被 rev7 持久暂停替代；其他非临时错误仍按当前服务规则处理，见[匹配说明](../matching.md)。

<a id="atlas-players"></a>

## Atlas 玩家查询与图片（2026-11-08～10）

- Atlas 成为默认来源，显式单模式查询；账号 ID 通用，利用已有映射/名单减少搜索。上游故障可回退到明确标注来源的 tarkov.dev 快照；本地预算耗尽是冷却，不借回退掩盖额度状态。
- 刷新是查询末尾的标记，跳过插件资料缓存，不承诺绕过上游缓存。查询/刷新次数和个人间隔由插件限制；仅未发送的尝试可按相应规则退还用户次数。
- 玩家、竞技场图片分别设计。成就中文读取 Atlas 字段，缺失时按字段回退英文，不编造翻译；基础物品图不等于真实改装装备图。武器拼图试验未成为当前承诺。
- 原始查询历史与周报数字样本分库，保留期及隐私动作不同。图片、字体、资料缓存不能混为一种缓存政策。
- 完整 Noto Sans SC 统一用于所有图片，首次下载校验、后续复用；裁剪字库流程已移除。开发命令见[开发指南](../development.md)。
- 2026-11-08 探测中的 busy、耗时与错误仅是时点证据，不能继续作为当前“功能尚未接入”的理由。原始记录见[Atlas 探测](../atlas-probe-record.md)。

<a id="weekly"></a>

## 玩家周报（2026-11-10）

- 维护者确认上游放宽后允许名单内夜间采样；这是 Atlas 后台请求的唯一例外。UTC+8 03:00～09:00，一步最多一个 HTTP，相隔 120 秒加随机 20～60 秒；昵称搜索和取档案分两步，白天不补拉。
- PVP/PVE/赛季已实现；Arena 规划统一转到 [checklist](../../checklist.md#arena-weekly)。不做订阅/退订命令，不批量遍历玩家。后台采样不套用前台个人次数规则，但仍受共享准入/暂停约束。
- 单独的 `weekly.sqlite3` 保存压缩数字、名单解析、采样进度和播报记录；不用受隐私开关与短保留期影响的原始查询库当基线。移出名单/解绑不立即删除历史，由保留期清理。
- 以最新样本向前滚动近七天、逐段计算累计差；计数下降作为重置处理。凌晨采样的每日场次归入前一天，娱乐用途不追求逐局精确；最新样本超过三天不出报告。
- 命令只读本地样本；按需查询档案可顺带采样，但未解析昵称名单存在 O01。个人报告与排行覆盖提示差异见 O02，均仅记录。
- 每周自动播报只发排行图，目标必须填写，错过超过六小时不补发，每图最多三次；没有文字/Markdown 或大模型评语。
- v0.6.1 补齐单次请求、夜间截止、前后台取消隔离、样本校验、样本/进度事务和昵称别名合并。旧零值样本无原始证据不能可靠还原，不猜测修复或清库。
- 自动化与维护者报告的主动推送可用，不代替一次完整夜间采样及具体聊天平台验收。

<a id="rev7"></a>

## Atlas rev7（2026-11-11）

依据维护者提供的六页《Atlas 外部白名单與API使用说明 rev7.pdf》，附件 SHA-256 为 `40301fde03039ea77b19bac46740e78457fadbd16e32ab61d78292dc77771ec1`。审查基线 `141e04b` / v0.6.1；第 1～4 项在 `de6e2a6` 完成。曾基于 v0.4.8 得出的“尚未接入 Atlas”结论已撤回。

- **T01，本地预算**：默认 15/200，分钟设置上限 15；保留更低配置、共享间隔和个人限制。不在当前文档重复列上游额度，预算不是目标请求速率。
- **T02，统计请求**：夜间显式 `art=0`，普通请求保留完整资料语义。缓存/负结果/在途键含 `(mode, account_id, include_art)`，仍共用容量上限；统计响应不能覆盖完整资料。
- **T02，历史迁移**：旧行新增 `include_art` 默认为完整请求语义，不推断实际是否有图片；同账号/模式/时间只允许统计向完整升级，不降级、不全库重写。后台单次请求仍与前台合并任务隔离。
- **T03，改名核验**：使用 `live=1`，只有唯一候选且新资料名称吻合才允许替换 ID；歧义或核验失败拒绝昵称绑定，普通查询按已有 ID 展示时须提示。已发送请求不能因后续本地拒绝而退还次数。
- **T04，访问暂停**：players 和 matching 分范围；401/403 持续暂停，用 `atlas-access.json` 保存有界状态元数据，不记录玩家/消息/密钥。等待前、获得共享入口后、预留预算前检查，避免排队请求漏过暂停。
- **T04，恢复**：管理员一次性动作先复位并保存，再允许下一次正常查询单次探测；保存失败不解锁，不立即联网、不清预算、不缩短有效上游等待。探测失败或取消再暂停；普通重载不恢复。损坏状态按暂停处理。
- **T04，采样**：暂停时不消耗名单玩家重试机会；夜间截止和取消隔离保持。首次发送前加载状态，缺文件按首次使用处理；不把无效持久化当作“已恢复”。
- **T05/T06**：昵称真实场景、点号兼容与缓存/历史政策未实施；决策分支和验收条件集中到 checklist。`TarkovCitizenAA` 仅人工边界，不是已证实生产缺陷。
- **验证**：实施记录新增 29 项，Python 3.12/3.13 各 569 项通过，含包检查；虚构数据和本地 HTTP/SDK 替身，无真实 Atlas/key/玩家/群消息。本地 Windows 后续审查的差异另见 checklist，不能混写成全平台通过。

### 接口边界与未启用能力

- 玩家 API 固定 `https://www.eftforge.com/atlas/api`，显式 `season/pvp/pve/arena`。只需统计使用 `art=0`；改名核验用 `live=1`。昵称规则与聊天入口兼容范围的差异仍待决定。
- 密钥及 lookup/changes/early 权限、玩家索引、封禁推测、full3d 和变更集是独立能力，未启用不等于违规。若将来接入，须重核原文与当时规则，不直接照搬历史摘要。
- 封禁结果仅能表述为推测；不能用搜索结果判断封禁。按账号渲染的 302 不构成放开通用重定向的理由；固定渲染图和临时图片地址的缓存语义不同。
- 变更集的 `season` 映射为 `eft`；cursor 只能在详情和大值可靠处理后提交，不越过 pending。425 按 Retry-After 等待；即使有 early 权限，公开播报仍须遵守 public_at。
- 429 与带等待头的相关失败不能靠换模式/接口绕过；401/403 是访问处理问题，不提示换代理继续尝试。404/503 需按具体接口区分，不误报不存在。
- rev7 的 JSON 禁缓存总述与图片、索引、matching 的专门规则需要区分；内部 TTL、原始历史、数字样本和合并边界待提供方明确。不创建缓存转发层，不自行删用户历史。
