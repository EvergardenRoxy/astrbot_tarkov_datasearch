# 归档：物品查询功能（item / 物品）

> **状态：已从项目剥离并封存（2026-10-24，维护者决定）。** 原因：物品查询无法使用俗称检索（需要长期维护复杂的俗称对应表），按名称查询的命中率和使用效率都不理想，被判定为低效功能。本文保存当时的设计与实现说明，供以后重新评估；当前插件不再含有任何物品查询代码、配置项、字体字形或测试。

## 当时的实现要点（摘要）

- 命令：`item <名称>` 查三个模式的共同属性；`item <pvp|pve|season> <名称>` 查指定模式价格、限制和属性差异；别名 `物品`、命名空间 `tarkov item ...`；`id:<24位ID>` 精确查询；同名候选最多 25 个；分页续查 `item 页 <编号> <页码>`。
- 配置项（已删除）：`items_enabled`（默认关）、`item_details_enabled`、`item_flea_enabled`、`item_trader_enabled`、`item_images_enabled`。
- 数据：各模式 `/items` 和 zh/en 字典，本地 `item-catalog.sqlite3` 索引；可选缩略图缓存 `item-icons`（7 天、128 张/32 MiB）。
- 删除的限制与教训：名称检索只覆盖官方中英文全名、简称和规范化名称，**不含玩家俗称**；加入俗称需要手工维护映射表，不可持续。通用属性核对要联结三个模式的数据，首次加载约 17 MB × 3，代价高于收益。

## 5. 物品对象、价格和属性查询

数据源：各模式的 `/items`；需要展示商人名时加载对应模式的 `/traders`。翻译分别获取 `_zh` 与 `_en`，并按响应中的 JSONPath 处理。材料和物品关系保留 ID，不修改上游对象。

### 通用属性与模式数据分层

统一使用同一个物品 ID 连接 PVP/PVE/赛季数据，维护 `CommonItem` 和 `ModeItemData(mode, itemId)` 两层。跨模式共享的是物品身份及核对后的共同字段，不能共享带模式的价格对象。

- `/item <名称>`：输出通用属性图片。白名单候选包括名称、ID、图片、重量、占格、分类，以及弹药伤害/穿深、护甲等级/材质、药品治疗参数等类型属性；只有在各模式可用快照中一致且完成所需模式核对后，才标为共同属性。
- 初次构建通用对象时按需下载三个模式并建立缓存；跨模式核对与索引构建放在线程执行，后续按需条件复查。部分模式获取失败时说明“通用属性跨模式核对未完成”，只展示已能确认的身份信息，不把 regular 的值伪装成三模式共同属性。
- `/item <模式> <名称>`：输出该模式数据图片，顶部仅保留识别物品所需的名称/ID，主体展示跳蚤价格、商人买卖报价、购买/解锁/交易限制，以及确实与其他模式不同的属性。公共属性不在主体中重复堆叠；可以提示通用属性查询命令。
- 字段在模式间不一致时不进入共同字段集合；显式模式图片注明差异及对比依据。区分字段缺失、明确为 0、不适用和接口失败，不把它们当成相等。
- 当前未完成对比时，显式模式仍可展示已获取的该模式价格及条件，但不能把未核对的属性断言为独有。某物品不在该模式里时返回图片说明，不显示其他模式的价格。

### 查询对象与索引

新增独立 `ItemCatalog`，维护物品对象与中文名、英文名、简称、`normalizedName` 索引。匹配优先级：显式 ID → 名称精确匹配 → 忽略大小写匹配 → 包含匹配。候选结果也绘为图片，列出名称、ID 及下一步命令；不把同名候选直接当成唯一结果。通用查询用跨模式索引，指定模式查询用该模式索引。

优先采用本地 SQLite 搜索索引和原始 JSON 磁盘缓存；按模式延迟加载，数据解析/建索引放到线程中，同一资源的并发请求合并。索引重建成功后原子替换；失败保留旧版本。中文词典与基础数据各自维护版本和 ETag。

### 两类图片的内容

- 跳蚤价格：最新扫描最低价、24 小时均价/最低/最高、报价数量及扫描时间。无报价、禁跳蚤、未解锁条件分开显示；不是逐笔成交记录，也不是承诺当前立即能买到。
- 商人价格：分“从商人购买”和“卖给商人”；显示原币价格、折合卢布、商人等级、任务解锁、限购。条件性最优报价必须带购买条件，不假装对所有玩家可用。
- 通用属性图：名称、占格、重量、类别和物品 ID；不出现默认模式或任意模式价格。
- 属性按 `propertiesType` 展示并进行共同字段核对：弹药看伤害/穿深/初速；护甲看等级/耐久/材质；枪械看人机/后坐力/射速；药品看治疗/使用时间/效果。缺字段不填造数值；有模式差异的字段移入模式图。

首版不增加制造利润、易物利润或历史价格画图命令；它们需要各自的成本模型和设置开关，可在基础物品查询稳定后独立扩展。

分别构建通用属性卡片和模式数据卡片，并在首版同时实现图片 renderer；图片不是后续补充项。主结果尽量一张图，内容超长时按完整区块分页；页脚标明模式或“通用属性”、对比/扫描时间和来源。图片失败时只发简短错误提示，不自动改发完整文字结果。


## 14. 物品查询阶段进度

已实现 `/item 名称`、`/item pve 名称`、`/item pvp 名称`、`/item 赛季 名称`、中文 `/物品` 和命名空间 `/tarkov item ...`。支持中文/英文全名、简称、多词名称与 `id:24位ID`；模式词开头的物品名可将整个名称加引号。另支持本次目录中的虚拟狗牌 ID `customdogtags12345678910`，其缩略图保持省略。名字不明确时先返回候选图片，按完整匹配、忽略大小写、包含匹配分级检索，包含匹配优先名称前缀/词首，保留总匹配数并列出前 25 件，须选 ID 或补充名称。

`items_enabled` 默认 false；`item_details_enabled`、`item_flea_enabled`、`item_trader_enabled`、`item_images_enabled` 默认 true，均依赖总开关。保存重载生效。属性、跳蚤、商人可分别关闭；关闭属性核对时不带模式查询返回提示图，显式价格查询只请求所选模式。短命令开关现停用六个状态/Boss/物品实际处理器，保留命名空间。QQ 官方提及后的斜杠入口也已接入。

物品源为各模式 `/items` 和独立 zh/en 字典；属性分型读取 `properties.propertiesType`。通用查询按 ID 联结三个模式，只有存在且一致的白名单属性进入共同图；属性类型不同或缺失时不将同值字段视为共同语义。缺失、null 与零分开，部分模式失败时只展示身份并说明核对未完成。模式查询只显示选定模式价格、限制和已核对差异，不自动换模式。价格不开启时不会出现在通用图；名称/属性翻译缺失逐级回退英文或上游值。

白名单覆盖体积、重量、堆叠、分类和主要弹药、武器、护甲、容器、医疗、食物等参数；护甲部位只投影部位/等级/耐久/材料/覆盖区，不将部位基础价混入共同属性。未知属性和装备完整兼容图尚未提供，不宣称已展示原始对象全部字段。跳蚤展示扫描最低价、24 小时统计、数量/扫描时间与禁跳蚤/等级限制，零价不当作免费。商人买入与卖出分开，保留币种、折算、等级、任务解锁、限购和补货量；只按需加载对应商人/任务名称，失败保留 ID。获取/检查和物品更新/扫描时间分开，均注明 GMT+8。

`item-catalog.sqlite3` 按模式保存投影对象与中英文名称索引。公共资源继续共用原始磁盘缓存；物品索引按内容、字典和版本签名重建，相同内容只更新元数据。下载共享并发任务，JSON/翻译/索引工作在线程中串行构建，SQLite 事务原子替换；失败保留旧索引，允许的上游故障回退明确标旧。空目录不覆盖已有索引，损坏身份/数值/商人报价在公共缓存接收前拒绝。没有专用后台轮询。

所有新查询及禁用、权限拒绝、无结果、候选、异常均为本地图片；分页测量/绘图失败仅给简短文字错误。长表每次回复一页及冻结快照续查 `tarkov item 页 <编号> <页码>`，包含全部已列候选/区块；至多保留 1 小时、16 组、16 MiB，容量不足可提前淘汰。续查不刷新价格，展示开关改变后需重新查询，不能通过旧图绕过关闭的价格区块。

物品缩略图为可选的独立按需缓存：只接受所选 24 位 ID 的固定 assets 路径，7 天、最多 128 张/32 MiB，失败不会阻断文字内容卡片。不会下载候选列表全部图片，不新增定时任务，也不会触发 Boss 头像更新。扩充随包 CJK 字形语料以覆盖已核对的物品、商人、任务标签；不打包原始物品数据或游戏图片，包体仍低于 1 MiB。

验证：307 项测试通过，最后的错误图片分页故障路径另有定向回归；AstrBot 4.16.0 路由回放扩至 135 项。真实 Salewa 查询完成三个目录和六份语言资源的首次加载、PVE 商人/任务名字解析、价格隔离、通用/模式图片以及候选图检查；重复查询和候选检索无额外公共数据请求，缩略图只下载一次，未启动后台任务或更新 Boss 头像。图像送达仍待 QQ 实机验收；不新增历史价格图、制造/易物利润或玩家档案输出迁移。README/checklist 保持不变。
